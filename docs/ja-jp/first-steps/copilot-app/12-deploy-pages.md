Space Quiz を GitHub Pages にデプロイして、誰でも利用できるようにします。Copilot はワークフローを準備し、デプロイを案内できますが、変更を確認し、サイトが公開されたことを確かめるのはユーザーの責任です。

このレッスンでは、次のことを行います。

- GitHub Pages へのデプロイを Copilot に構成させます。
- マージする前にワークフローとプルリクエストを確認します。
- デプロイを追跡し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、誰もが簡単に試せる方法はまだありません。単一ファイルのサイトを GitHub Pages で公開すれば、サーバーやランタイム依存関係を追加せずに、公開 URL からアクセスできます。

## Copilot にサイトのデプロイを依頼する

`space-quiz` の Copilot アプリのセッションで、次のプロンプトを送信します。

```plaintext
このリポジトリで GitHub Pages を有効にしてください。必要に応じて Web サイトをビルドし、GitHub Pages にデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリの説明とローカルでの実行方法を記載した README を追加してください。これらの変更を含むプルリクエストを作成し、必須チェックに合格したらマージしてください。デプロイが成功するまで監視し、その後、公開された Web サイトの最終 URL を報告してください。Pages を有効にする権限やマージする権限がない場合は、私が何を承認または実行すればよいかを正確に伝えてください。サイトが公開されるまでは成功したと報告しないでください。
```

> [!WARNING]
> このプロンプトでは、エージェントにプルリクエストの作成とマージ、およびリポジトリの Pages 設定の変更を依頼します。続行する前に、diff、デプロイ権限、GitHub の承認要求を確認してください。

## ワークフローを確認してデプロイを検証する

1. リポジトリに README がない場合に限り、README が追加されていることを確認します。
2. ワークフローのビルドとデプロイの手順を含め、プルリクエストの変更を確認します。
3. 必須のプルリクエストチェックに合格した後にのみマージします。
4. GitHub Actions のデプロイ実行が成功するまで確認します。
5. 報告された URL を開き、Space Quiz が読み込まれることを確認します。

エージェントが Pages を有効にできない場合やプルリクエストをマージできない場合は、提示された具体的な手順に従ってください。デプロイが成功し、公開サイトが読み込まれるまでは、タスクを完了扱いにしないでください。
